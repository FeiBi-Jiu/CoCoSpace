## 实现步骤

### 1. 商店开启流程
```
玩家靠近商店据点且据点已清完 → 服务器下发 S2CShopOpen
  └─ ShopUI.Open(msg) 打开面板
  └─ 渲染私人货架（myShelfRoot）
  └─ 渲染队友货架（teammateShelfRoot）
```
- 只有据点清完（所有怪死完）才能交互，由服务器判定并下发 `S2CShopOpen`
- 客户端不做"据点是否清完"的判定，只响应服务器消息

### 2. 货架结构
```
S2CShopOpen {
  ShopItem[] my_items       // 自己的私人货架
  ShopItem[] team_items     // 队友货架（合并展示）
  uint32 owner_entity_id    // 队友货架归属者
}

ShopItem {
  uint32 item_id
  string name
  uint32 price
  uint32 type               // 武器/技能/道具
  string icon_path
}
```

### 3. 双 Tab 切换
- Tab1：我的货架（`myShelfRoot`）
- Tab2：队友货架（`teammateShelfRoot`）—— 可切换不同队友
- `RenderShelf` 已实现渲染逻辑，清空旧卡片后实例化新卡片

### 4. 购买流程
```
点击商品 → Buy(itemId, owner)
  └─ 发送 C2SBuy { item_id, for_teammate_entity_id }
        └─ owner=0 表示给自己买，owner=队友ID 表示替队友买
  └─ 服务器校验金币、扣钱、发货
  └─ 服务器广播 S2CBuyResult { success, item_id, buyer, receiver, new_gold }
        ├─ 成功 → 更新 HUD 金币，提示购买成功
        └─ 失败 → 提示"金币不足"
```
- `ShopUI.Buy` 已实现意图发送，只发"买什么/替谁买"，不发结果
- "钱够不够"显示：客户端可根据快照中的 `gold` 与 `price` 比较，做灰显/置灰按钮（纯表现，不阻止购买）

### 5. 金币分账显示
- 据点清完后服务器分账，下发 `S2C_GoldShare` 或更新快照 `gold`
- HUD 金币数变化时播放数字滚动动画
- 可选：显示"获得 XX 金币"飘字

## 与后端对接
| 方向 | 消息 | 说明 |
|---|---|---|
| S→C | `S2CShopOpen` | 商店货架内容 |
| C→S | `C2SBuy` | 购买意图：item_id + 替谁买 |
| S→C | `S2CBuyResult` | 购买结果：成功/失败 + 新金币 |
| S→C | `S2C_GoldShare` | 据点贡献分账 |

## 关键技术点
- **清完据点才可交互**：由服务器判定，客户端只响应 `S2CShopOpen`
- **替队友买**：`for_teammate_entity_id` 字段区分给自己买还是替队友买
- **钱够不够是表现**：客户端可灰显按钮，但购买成败由服务器判
- **货架是私人的**：每个玩家看到的货架不同（服务器按玩家生成）
