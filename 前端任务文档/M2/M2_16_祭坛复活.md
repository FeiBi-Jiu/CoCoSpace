# M2 #16 · 祭坛复活

## 所属阶段
M2 · 灰盒完整功能

## 任务目标
引导条交互复活鬼魂，复活过程全队可见。

## 前置依赖
- 前端：背包引导状态机（M2 #15）、鬼魂形态（M2 #17）
- 后端：引导状态机（B2 #14）、鬼魂系统（B2 #15）

## 已有骨架
- `Assets/Scripts/Interaction/AltarRevive.cs` — 祭坛复活交互（长按 E 引导）

## 实现步骤

### 1. 祭坛交互流程
```
鬼魂靠近祭坛 → near = true → 显示引导环
长按 E → progress += dt / holdTime（holdTime = 2s）
  ├─ 受击 → progress 归零（由服务器判定，客户端表现）
  └─ progress >= 1 → 发送 C2SRevive { altar_id }
服务器校验 → 应用复活 → 广播 S2C_Revived { entity_id, altar_id }
  └─ 鬼魂玩家恢复肉身
  └─ 全队看到复活演出
```

### 2. 引导环表现
`AltarRevive` 已实现：
```csharp
progressRing.gameObject.SetActive(near);   // 靠近才显示
progressRing.fillAmount = progress;         // 引导进度
```
- 引导环是世界空间 UI（`Image` 在祭坛上方）
- 全队可见：引导环状态由服务器同步，所有客户端都能看到谁在复活

### 3. 复活过程全队可见
- 服务器在引导过程中广播 `S2C_ReviveProgress { entity_id, altar_id, progress }`
- 所有客户端更新对应祭坛的引导环
- 复活完成时播放复活特效（光柱/粒子）
- 鬼魂玩家的 `GhostForm` 组件切换回正常形态

### 4. 受击打断
- 引导中鬼魂被击中 → 服务器判定打断 → 广播 `S2C_ReviveInterrupted`
- 客户端：引导环归零，引导中断
- 与背包引导共用打断逻辑（B2 #14）

### 5. 灰盒简化
- 当前 `AltarRevive` 在客户端本地判定引导进度
- 正式版：引导进度由服务器下发，客户端只做表现
- 祭坛 ID 在地图布局中定义，`altarId` 与服务器对齐

## 与后端对接
| 方向 | 消息 | 说明 |
|---|---|---|
| C→S | `C2SRevive` | 复活意图：altar_id |
| S→C | `S2C_ReviveProgress` | 引导进度（全队同步） |
| S→C | `S2C_Revived` | 复活完成 |
| S→C | `S2C_ReviveInterrupted` | 受击打断 |

## 关键技术点
- **引导状态机复用**：与背包共用"计时+受击打断"
- **全队可见**：复活引导过程对全队可见，强调协作
- **复活条件由服务器判**：是否有祭坛、是否是鬼魂、引导是否完成，都由服务器判定
- **鬼魂才能复活**：非鬼魂玩家交互祭坛无响应
