# M2 #23 · 结算页

## 所属阶段
M2 · 灰盒完整功能

## 任务目标
团灭/通关后数据对比：伤害/贡献/击杀。

## 前置依赖
- 前端：Proto 消息对接（M0 #2）
- 后端：结算统计（B2 #20）

## 已有骨架
- `Assets/Scripts/UI/ResultPanel.cs` — 结算面板

## 实现步骤

### 1. 结算触发
- 团灭（所有玩家死亡且无鬼魂可复活）或通关（Boss1 死亡）
- 服务器下发 `S2C_GameResult { result, stats[] }`（冷路径 JSON）
- 客户端打开 `ResultPanel`

### 2. 结算数据结构
```
GameResult {
  bool   victory              // true=通关，false=团灭
  PlayerStat[] stats          // 各玩家数据
}

PlayerStat {
  uint32 entity_id
  string player_name
  uint32 damage_dealt         // 总伤害
  uint32 contribution         // 贡献分
  uint32 kills                // 击杀数
  uint32 death_count          // 死亡次数
  // 扩展：治疗量、搬运次数、复活次数等
}
```

### 3. 数据对比展示
- 列表形式展示所有玩家数据
- 每列可排序（伤害/贡献/击杀）
- 高亮最高值（如伤害最高者标红）
- 显示自己的行高亮

### 4. 反射弹幕归属
- 反射弹幕的击杀归反弹者（B2 #20）
- 结算数据已由服务器正确归属，客户端直接展示
- 无需客户端额外处理

### 5. 结算后操作
- "返回大厅"按钮 → 断开连接/重新登录
- "再来一局"按钮 → 重新进房（若支持）
- 灰盒阶段只做"返回大厅"

## 与后端对接
| 方向 | 消息 | 说明 |
|---|---|---|
| S→C | `S2C_GameResult`（冷路径 JSON） | 结算数据：胜负 + 各玩家统计 |

## 关键技术点
- **结算数据服务器算**：伤害/贡献/击杀全由服务器统计，客户端只展示
- **反射归属已处理**：服务器把反射弹幕击杀归反弹者，客户端直接显示
- **冷路径 JSON**：结算是低频一次性数据，用 JSON 不用 protobuf
- **数据对比**：高亮最高值，让玩家有竞争感
