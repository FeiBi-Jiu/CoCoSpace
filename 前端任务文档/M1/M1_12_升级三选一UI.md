# M1 #12 · 升级三选一 UI

## 所属阶段
M1 · 能玩

## 任务目标
服务器对选择者个体缓速（子弹时间是服务器规则），客户端纯表现；超时自动选。

## 前置依赖
- 前端：Proto 消息对接（M0 #2）
- 后端：经验/升级 roll（B1 #10）

## 已有骨架
- `Assets/Scripts/UI/UpgradeChoiceUI.cs` — 升级选择 UI

## 实现步骤

### 1. 升级流程
```
玩家经验满 → 服务器广播 S2C_LevelUp { entity_id, choices[] }
  └─ 是自己 → 打开三选一面板，同时服务器对自己开启子弹时间
  └─ 是队友 → 显示"队友 XXX 正在选择"提示
玩家点击选项 → C2S_UpgradeChoice { choice_index }
  └─ 服务器应用效果，关闭面板，子弹时间结束
超时未选（如 10s）→ 服务器自动选第一个，下发 S2C_UpgradeTimeout
```

### 2. 三选一选项结构
```
UpgradeChoice {
  uint32 choice_id
  string name           // 技能名
  string desc           // 描述
  uint32 icon_id        // 图标 ID
  uint32 rarity         // 稀有度（决定颜色/边框）
  // 数值由服务器应用，客户端只显示
}
```

### 3. 子弹时间表现（纯表现）
- 服务器规则：对选择者个体时间缩放（如 0.3x）
- 客户端表现：收到 `S2C_LevelUp`（自己）后，将 `Time.timeScale` 设为 0.3
- 只有选择者自己被缓速，其他玩家正常
- 选择完成/超时后 `Time.timeScale` 恢复 1.0
- **注意**：`Time.timeScale` 会影响所有本地逻辑，需确保网络收发（`KcpNetClient.Update`）用 `Time.unscaledDeltaTime`

### 4. 超时自动选
- 面板显示倒计时（如 10 秒）
- 倒计时结束时若未选择，客户端自动发送 `C2S_UpgradeChoice { choice_index = 0 }`
- 或服务器超时自动选，客户端收到 `S2C_UpgradeTimeout` 后关闭面板
- 推荐：服务器做超时判定，客户端只显示倒计时

### 5. UI 布局
- 三个选项卡片横向排列
- 每个卡片：图标 + 名称 + 描述 + 稀有度颜色边框
- 顶部：倒计时进度条
- 灰盒阶段用 uGUI 即可，图标可用纯色占位

## 与后端对接
| 方向 | 消息 | 说明 |
|---|---|---|
| S→C | `S2C_LevelUp` | entity_id + 3 个选项 |
| C→S | `C2S_UpgradeChoice` | 选择的选项 index |
| S→C | `S2C_UpgradeTimeout` | 超时自动选择结果 |
| S→C | `S2C_UpgradeApplied` | 升级效果已应用（确认） |

## 关键技术点
- **子弹时间是服务器规则**：客户端只做表现（`Time.timeScale`），服务器实际控制游戏速度
- **数值不在客户端算**：选项效果由服务器应用，客户端只显示描述
- **超时由服务器判**：客户端倒计时只做显示，避免作弊
- **unscaledDeltaTime**：子弹时间时网络/UI 不能停，用 `Time.unscaledDeltaTime` 驱动

## 验收标准
- [ ] 升级时弹出三选一面板，显示 3 个选项
- [ ] 自己选择时游戏变慢（子弹时间），队友不受影响
- [ ] 点击选项后面板关闭，效果应用
- [ ] 超时未选自动选第一个
