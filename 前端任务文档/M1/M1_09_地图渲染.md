# M1 #9 · 地图渲染

## 所属阶段
M1 · 能玩

## 任务目标
接收服务器下发的完整布局数据（据点/道路/属性/道具），一次性构建静态层，构建后缓存，局内不动。

## 前置依赖
- 前端：Proto 消息对接（M0 #2）
- 后端：地图生成器（B1 #6）→ 输出 `MapLayout`

## 已有骨架
- `Assets/Scripts/Map/MapBuilder.cs` — 地图构建器（据点平面/道路条带/道具方块）
- `Assets/Scripts/Net/Gen/Map.cs` — 地图 proto 类（`MapLayout` / `Road` / `Node` / `Prop`）

## 实现步骤

### 1. 地图布局消息格式（冷路径 JSON）
```
MapLayout {
  Node[]  nodes   // 据点
  Road[]  roads   // 道路（折线）
  Prop[]  props   // 场景道具
}

Node {
  uint32 node_id
  float  x, z        // 据点中心坐标
  float  radius      // 据点半径
  uint32 attribute   // 元素属性（火/水/...）
  uint32 type        // 普通/商店/祭坛/Boss
}

Road {
  uint32 road_id
  Point[] points     // 折线点序列
  float  width       // 道路宽度
}

Prop {
  uint32 prop_id
  float  x, z
  uint32 type        // 火药桶/油瓶/血瓶...
}
```
- 走冷路径（JSON over WebSocket），开局一次性下发
- 纯数据，不含任何渲染信息

### 2. 静态层构建
`MapBuilder.Build(MapLayout layout)` 已实现：
- **据点**：`Plane` 缩放为 `radius`，按 `attribute` 染色
- **道路**：沿折线生成条带 Mesh（`BuildRoadStrip`），每段两个三角形
- **道具**：`Cube` 占位（火药桶/油瓶等）
- `StaticBatchingUtility.Combine` 合并静态网格，降低 DrawCall

### 3. 构建后缓存
- `MapBuilder` 构建完成后，将所有静态物体设为 `Static`
- 局内不再修改（灰盒定稿：不做动态地图变化）
- 切换关卡时销毁旧地图，重新构建

### 4. 属性染色
- `attributeColors` 数组按属性索引取色
- 火=红、水=蓝、雷=黄、毒=绿...（与元素表一致，见 M2 #19）
- 灰盒阶段用纯色，正式版可换材质/贴图

### 5. 碰撞
- 据点和道路地面加 `MeshCollider`（或简化为 `BoxCollider`）
- 道具（火药桶/油瓶）加碰撞，可被子弹引爆
- 墙体/边界碰撞由服务器钳制（B1 #7），前端做视觉阻挡即可

## 与后端对接
| 方向 | 消息 | 说明 |
|---|---|---|
| S→C | `S2C_MapLayout`（冷路径 JSON） | 完整地图布局，开局一次下发 |
| 依赖 | 地图生成器输出格式（B1 #6） | 据点/道路/道具/属性结构 |

## 关键技术点
- **不做 seed 双端生成**：灰盒定稿，服务器生成完整布局下发，避免浮点确定性坑
- **一次性构建**：构建后缓存，局内不动，性能好
- **静态批处理**：`StaticBatchingUtility.Combine` 是几百个物体流畅的关键
- **渲染与数据分离**：`MapLayout` 是纯数据，`MapBuilder` 负责转成 Unity 物体

## 验收标准
- [ ] 服务器下发地图后，客户端能正确渲染据点（圆形场地）和道路（折线条带）
- [ ] 据点按属性染色
- [ ] 道具（火药桶/油瓶）摆放在正确位置
- [ ] 构建后局内地图不再变化，帧率稳定
