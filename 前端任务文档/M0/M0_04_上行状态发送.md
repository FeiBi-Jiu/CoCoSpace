# M0 #4 · 上行状态发送

## 所属阶段
M0 · 把线连上

## 任务目标
定频上报自己的移动坐标 + 开火/交互意图，严格遵守"上行只发意图不发结果"的纪律。

## 前置依赖
- 前端：角色控制器（M1 #6）提供输入数据
- 后端：意图接收与转发（B1 #7）

## 已有骨架
- `Assets/Scripts/Net/IntentSender.cs` — 意图发送器（20Hz 定频）
- `Assets/Scripts/Player/InputSnapshot.cs` — 输入快照数据结构
- `Assets/Scripts/Player/PlayerController.cs` — 玩家控制器（产生输入）

## 实现步骤

### 1. 输入快照结构
`InputSnapshot` 需包含：
```
Vector3 pos              // 本地坐标（移动权威在客户端）
float yaw                // 朝向
bool firePressed         // 是否按下开火
uint skillId             // 技能 ID
uint interactTargetId    // 交互目标实体 ID
float interactProgress   // 引导进度（0~1）
```
- `PlayerController` 每帧更新 `IntentSender.LatestInput`
- `IntentSender` 按 `sendHz`（默认 20Hz）采样最新输入打包发送

### 2. 意图消息 `C2S_Intent`
```
C2S_Intent {
  uint32 seq              // 自增序列号
  MoveIntent move         // 移动意图：x, z, yaw
  FireIntent fire         // 开火意图：x, z, yaw, skill_id（可选）
  InteractIntent interact // 交互意图：target_id, progress（可选）
}
```
- `IntentSender.Update` 已实现打包逻辑，根据 `firePressed` / `interactTargetId` 决定是否填充对应字段

### 3. 纪律：只发意图不发结果
- 移动：发坐标，不发"我走到了"——服务器做钳制校验后广播
- 开火：发"我要开火"（方向+技能），不发"我打中了谁"——服务器做命中判定
- 交互：发"我要交互"（目标+进度），不发"我完成了交互"——服务器判定完成
- 任何客户端声称的结果（伤害/拾取/金币）一律不发，由服务器重算

### 4. 序列号与丢包
- `seq` 自增，后端可用于去重和乱序检测
- KCP 可靠通道保证有序，灰盒阶段无需额外处理
- 若切换到不可靠通道，需处理丢包（关键意图用可靠，高频移动用不可靠）

### 5. 频率配置
- `sendHz = 20`（Inspector 可调）
- 移动坐标 20Hz 足够配合 100ms 插值延迟
- 开火是事件型，按下即可发，不受 20Hz 限制（灰盒阶段可合并到定频包中）

## 与后端对接
| 字段 | 说明 | 后端处理 |
|---|---|---|
| `move.x / move.z` | 本地坐标 | 速度上限校验、瞬移检测、撞墙校验 |
| `move.yaw` | 朝向 | 转发广播 |
| `fire.*` | 开火意图 | 命中判定、伤害结算 |
| `interact.*` | 交互意图 | 引导状态机、计时、受击打断 |

## 关键技术点
- 移动权威在客户端，服务器只做钳制——这是灰盒定稿，架构上隔离（见 `IMovementAuthority`）
- 灰盒阶段不做预测纠偏，服务器回传的坐标如果与本地差异大，灰盒直接以本地为准
- 上行坐标用于其他玩家看到你的位置，不是给自己用的
- `ProtoHash.Version` 随登录发送，确保协议一致

## 验收标准
- [ ] 客户端以 20Hz 频率发送 `C2S_Intent`
- [ ] 其他客户端能看到本客户端的移动（通过服务器广播的快照）
- [ ] 开火时只发送意图，不发送任何伤害/命中结果
- [ ] 尝试瞬移（速度超限）时被服务器钳制，位置被拉回
