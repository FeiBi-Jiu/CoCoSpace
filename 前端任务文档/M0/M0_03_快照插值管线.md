# M0 #3 · 快照插值管线

## 所属阶段
M0 · 把线连上

## 任务目标
接收服务器下发的状态快照，对远端实体做时间插值平滑渲染，消除网络抖动带来的瞬移感。

## 前置依赖
- 后端：快照格式定义 + 快照广播（B0 #4）
- 前端：Proto 消息定义对接（M0 #2）

## 已有骨架
- `Assets/Scripts/Snapshot/SnapshotBuffer.cs` — 快照环形缓冲（泛型，最多 32 帧）
- `Assets/Scripts/Snapshot/RemoteEntityView.cs` — 远端实体视图（插值渲染）
- `Assets/Scripts/Net/Gen/Snapshot.cs` — 快照 proto 类

## 实现步骤

### 1. 快照缓冲
`SnapshotBuffer<T>` 已实现核心逻辑：
- `Push(serverTime, snap)` — 入队，超过 32 帧丢弃最旧
- `Sample(renderTime, out from, out to, out t)` — 在 `renderTime = serverTime - interpDelay` 处取样
- `interpDelay = 0.1`（100ms）：渲染时刻比最新快照滞后 100ms，保证总有两帧可插值

### 2. 快照接收与存储
- `MsgDispatcher` 收到 `S2C_Snapshot` 后，按 `EntityId` 分发给各 `RemoteEntityView`
- 每个远端实体维护自己的 `SnapshotBuffer<EntitySnapshot>`
- 快照频率 20~30Hz（由后端决定），缓冲 32 帧 ≈ 1 秒冗余

### 3. 插值渲染
`RemoteEntityView.Update` 每帧：
```
renderTime = (serverTimeNow) - interpDelay
buffer.Sample(renderTime, out from, out to, out t)
  ├─ from == to → 直接用（只有一帧或滞后）
  └─ 否则 → Lerp(from.pos, to.pos, t) / Slerp(from.rot, to.rot, t)
```
- 位置用 `Vector3.Lerp`，旋转用 `Quaternion.Slerp`
- 灰盒阶段只插值 position，rotation 可直接取最新值

### 4. 实体生命周期
- 快照中出现新 `EntityId` → 实例化 `RemoteEntityView` prefab
- 快照中消失的 `EntityId`（连续 N 帧未出现）→ 销毁
- 自己的 `EntityId` 不渲染远端视图，由本地 `PlayerController` 控制

### 5. 服务器时间同步
- 登录时 `S2C_LoginAck` 下发服务器时间基准
- 本地维护 `serverTimeNow = localTime - rtt/2 + offset`
- RTT 通过心跳或快照时间戳估算

## 与后端对接
| 字段 | 类型 | 说明 |
|---|---|---|
| `server_time` | double | 快照的服务器时间戳 |
| `entities[]` | EntitySnapshot | 所有可见实体 |
| `entity_id` | uint | 实体唯一 ID |
| `type` | enum | 玩家/怪/Boss/掉落物/道具 |
| `x, y, z` | float（或定点） | 位置 |
| `yaw` | float | 朝向 |
| `state` | uint | 行为状态（攻击/移动/死亡…） |
| `hp` | uint | 生命值 |

## 关键技术点
- 插值延迟 `interpDelay` 是手感关键：太小会瞬移，太大会感觉拖
- 本地玩家不走插值，走 `LocalAuthoritativeMovement` 直接控制
- 灰盒阶段不做预测纠偏，服务器权威移动时再升级
- 缓冲溢出（>32 帧）说明网络拥塞，应丢弃旧帧而非新帧

## 验收标准
- [ ] 两个客户端互相看到对方立方体平滑移动，无明显瞬移
- [ ] 网络抖动 50~100ms 时画面仍平滑
- [ ] 新玩家进入房间后，已有玩家能看到其实体出现
- [ ] 玩家离开后实体在延迟内消失
