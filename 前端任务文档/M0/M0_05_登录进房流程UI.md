# M0 #5 · 登录/进房流程 UI

## 所属阶段
M0 · 把线连上

## 任务目标
实现最简陋可用的登录与进房界面，能输入房间号、连接服务器、进入游戏场景。

## 前置依赖
- 前端：KCP/QUIC 连接管理（M0 #1）、Proto 消息对接（M0 #2）
- 后端：登录/进房接口（B0）

## 已有骨架
- `Assets/Scripts/UI/LoginPanel.cs` — 登录界面逻辑
- `Assets/Scripts/GameRoot.cs` — 游戏入口/场景切换
- `Assets/Scripts/Net/IntentSender.cs` — `SendLogin` / `SendReconnect`
- `Assets/Scripts/Net/Gen/Login.cs` — 登录 proto 类

## 实现步骤

### 1. 登录界面元素
- 服务器 IP 输入框（默认 `127.0.0.1`）
- 端口输入框（默认 `7777`）
- 房间号输入框（RoomId）
- 玩家名输入框（PlayerName）
- "连接"按钮

### 2. 连接流程
```
点击"连接"
  └─ KcpNetClient.Instance.Connect(ip, port)
  └─ 等待 OnConnectedEvent
  └─ IntentSender.SendLogin(roomId, playerName)
  └─ 等待 S2C_LoginAck
        ├─ 成功 → 保存 SessionToken，进入游戏场景
        └─ 失败 → 提示错误（版本不匹配/房间满）
```
- `C2S_Login` 携带 `RoomId` / `PlayerName` / `ClientVersion` / `ProtoVersion`
- `S2C_LoginAck` 返回 `SessionToken` / `EntityId` / 初始快照 / 服务器时间基准

### 3. 进房后的初始化
- `GameRoot` 收到登录确认后：
  1. 实例化本地玩家 prefab，绑定 `EntityId`
  2. 启动 `SnapshotBuffer` 接收远端实体
  3. 启动 `IntentSender` 开始上报
  4. 切换到游戏场景

### 4. 错误处理
- 连接失败 → 提示"无法连接服务器"，允许重试
- 版本不匹配 → 提示"请更新客户端"
- 房间已满 → 提示"房间已满"
- 断线 → 触发 `OnDisconnectedEvent`，弹出重连按钮或自动重连

### 5. 灰盒简化
- 不做账号系统，房间号直接当会话用
- 不做匹配，手动输入房间号
- UI 用 uGUI 即可，不需要美术资源
- 灰盒阶段可以把 IP/端口/房间号硬编码为默认值，UI 只留一个"开始"按钮

## 与后端对接
| 方向 | 消息 | 关键字段 |
|---|---|---|
| C→S | `C2S_Login` | RoomId, PlayerName, ClientVersion, ProtoVersion |
| S→C | `S2C_LoginAck` | Success, SessionToken, EntityId, ServerTime, 初始快照 |
| C→S | `C2S_EnterRoom`（冷路径） | 可选，若进房走 HTTP/WebSocket |
| S→C | `S2C_RoomInfo`（冷路径） | 玩家列表、地图布局、配置表 |

## 关键技术点
- `KcpNetClient` 是 `DontDestroyOnLoad` 单例，切场景不丢连接
- 登录成功后必须保存 `SessionToken`，供断线重连用
- 冷路径数据（地图布局、配置表）可在登录后通过 WebSocket 一次性下发，缓存到 `TableManager`
- `GameRoot` 作为总入口，负责连接 → 登录 → 进场景的状态机

## 验收标准
- [ ] 输入 IP/端口/房间号/玩家名后能成功连接并进入游戏
- [ ] 两个客户端输入同一房间号能互相看到对方
- [ ] 连接失败时有明确提示
- [ ] proto 版本不匹配时登录被拒并提示
