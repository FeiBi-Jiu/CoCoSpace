# 多人肉鸽差异化设计文档

> **版本 v1** 
> 品类参照：元气骑士（俯视角弹幕 + 肉鸽局内构筑 + 合作闯关）
> 技术栈：Unity（前端渲染）+ Go（后端权威服务器）
>

---

# 第一部分：核心设计定稿

## 1.1 世界结构

- **开放路径地图，非房间制**：窄路连接宽**据点**，据点即波次竞技场、即刷怪点；仅 Boss 有专属房间
- **路径随机生成**，可来回折返；场景会刷新可交互道具（油桶、火药等）
- **战争迷雾**：只能看到已点亮区域
- **据点 = 节奏锚**：清过的据点及其到下一据点前的区域为"无打扰环境"（安全区）
- **位置死亡机制**：怪死于特定地点会产生特定类型的技能掉落——**空间即资源**，"在哪杀"是策略（与战争迷雾、鬼魂探图形成情报玩法）

## 1.2 战斗与操作

- 操作模型：**1 攻击键 + 2 主动技能**；每角色有自带技能和自带武器，武器自身也带技能/词条
- 弹幕为可交互实体（仅队友弹幕，详见 1.7）

## 1.3 构筑系统

**获取渠道（四条）**：

| 渠道       | 产出                           |
| -------- | ---------------------------- |
| 升级（怪掉经验） | 数值成长 + 技能三选一（子弹时间中进行）        |
| 精英怪      | 主动/被动技能                      |
| 商店       | 被动技能 + 道具                    |
| Boss     | 武器（各角色**自带武器的升级版**，更多武器后续设计） |

- **技能池**：MVP 各做 10 个主动 + 10 个被动
- **取舍压力**：单局技能获取总量 ≥ 8，远超携带上限（2 装备 + 2 备用）——**强迫玩家丢技能、优化构筑**，这是构筑深度的来源
- **升级选技能**：子弹时间（选择者局部缓速，非全队暂停）；窗口 5 秒左右，超时自动随机选择 🟡（防挂机拖全场）
- 构筑主线走技能，武器是里程碑式身份变更

## 1.4 背包与道具

- 背包容量：**1 把武器 + 2 个技能 + 3 种道具**（每种道具堆叠数不一）
- 开背包需**数秒引导，受击打断**——规则复用战斗系统，风险自调节：危险区"能开但开不完"，安全据点里"能开完"
- 道具（燃烧瓶、水瓶等）：商店购买的血瓶**可以**入背包；**怪物掉落的血瓶不可以**捡入背包，除非鬼魂搬运

## 1.5 死亡、鬼魂与复活

- **死亡 → 鬼魂**：无怪物仇恨；**拴绳**于存活玩家一定范围内（半径可配置，灰盒调参）；可探图、可跟随存活玩家并给 buff
- **鬼魂可搬运**：能捡起掉落技能/道具交给存活玩家——怪物掉落血瓶的唯一入库通道（死亡玩家 = 后勤位）
- **复活：祭坛制**。祭坛设于据点内；复活 = 引导数秒 + 受击打断（复用引导规则）。刚清完据点时复活是安全的，战斗中复活 = 全队护法的名场面
- **团灭（全队变鬼魂）= 本局失败**

## 1.6 仇恨与怪物 AI

- 怪物跟随玩家，**跟远了加速追赶**（反拉火车/反风筝）
- **仇恨规则：怪物更倾向攻击视野内得分更高的玩家**——强的人吸火力，弱的人有空间；由此自然生长出**隐身流**（脱战/甩仇恨）
  - 🟡 隐身边界三条建议：伤害破隐（防无敌风筝）、队友始终可见（防"像掉线"）、贡献照算（打伤害照样拿钱，隐身的代价是不当仇恨坦克）
- **两级距离惩罚**：
  - 轻度分离 → 怪物部分**攻击分裂**（提示靠近，且鼓励靠近触发弹幕交互）
  - 极端分离（如 A 在上一据点、B 在打新据点）→ 怪物**狂暴**：速度和攻击提升
  - 🟡 狂暴必须可读：怪物变色 + 音效 + UI 警告"队伍分散"

## 1.7 协同机制（本项目原创核心）

- **弹幕交互**：队友弹幕是可交互实体，可被**反射、折射**；双方弹幕**交汇产生第三种效果**
- 交互性作为**武器/技能词条**存在（如"反弹流"是 build 身份），不设为全局默认——保可读性 + 构筑深度
- **元素系统**：一张统一元素表（起步：火/水/油/雷），同时服务三个层——
  - 子弹的效果层（弹幕带元素）
  - 场景道具（油桶/火药 + 燃烧瓶/水瓶）
  - 位置死亡技能（火区死怪掉火系技能）
  - 弹幕交汇的第三效果 = 元素组合表（"组合语法"）
- **Boss 协同战例**（Boss1 设计意图）：Boss 对火易伤 → 玩家用油瓶/技能挂油 → 另一玩家挂火点燃；或 Boss 蓄力窗口内两人同时交大招**破甲跳阶段**

## 1.8 经济系统

- **金币**：怪物按难度掉落；小概率掉血瓶
- **分账**：据点内**贡献大的玩家多拿钱，每据点重新计算**——马太滚雪球（肉鸽爽点）但每据点翻篇给翻盘窗口
  - 🟡 建议留保底（贡献最低者约 30%），防弱势玩家彻底进不了商店
- **商店**：
  - 刷在**据点内**，清完怪才能交互（商店 = 据点奖励 = 节奏阀）
  - 随机刷 2 个被动技能 + 2 个道具（燃烧瓶、水瓶等）
  - **每人看到的商品不同**（私人货架）——截胡在物理上不可能
  - **全队离开商店范围后消失**
  - **可以替队友买**（UI 需可查看队友货架的 tab 🟡）

## 1.9 掉落与压力

- 掉落技能 **10 秒内未捡则消失，且会强化（附近的）怪物**（设计保留）
  - 🟡 四条护栏建议随实装验证：强化只作用于掉落点附近（空间局部化）；每只怪的强化有上限；吃技能的怪物高亮可读；鬼魂搬运作为泄压阀

## 1.10 Boss 与关卡结构

- **两关**；每关 = 5~8 波怪 + Boss；**通关 = 击败最终 Boss**
- **Boss 掉落**：各角色自带武器的升级版
- **Boss1（两阶段）**：元素协同弱点设计（挂油挂火/蓄力破甲跳阶段，见 1.7）
- **Boss2（一阶段，暂定）**
- **第二关差异**：新怪种更多、金币经验更高
- **跨关继承**：经验、金币继承（默认继承构筑成长，需实装写明）

## 1.11 数值基线（纸面推演起点）

- 玩家：约 100 血（角色间血量有差异）、约 10 点伤害；升级均增
- 怪物：初始 50 血 / 10 攻，越往后越强
- 升级曲线：第一关第一个据点升一级，之后频率递减
- 目标单局时长：约 25 分钟（两关，待纸面验证）

## 1.12 服务器与多人规则

- **人数上限 4 人**
- **经验分配**：队伍范围内共享（谁杀都算——鼓励抱团，与弹幕交互同向）
- **掉线处理**：**掉线即变鬼魂，重连即复活**——服务器权威架构的白送能力，掉线不毁局
- **结算画面**：团灭/通关后给本局数据对比（伤害/贡献/击杀）——多人最便宜的社交爽点
- **反射弹幕归属**：算**反弹者**的贡献（操作有奖励，金币/仇恨跟着贡献走）
- 🟡 沟通工具（轮盘 ping：标记敌人/技能/商店/危险）：**延后**至能玩测试后再做
- **反射弹幕的物理边界**：队友弹幕可否当盾牌等 exploit，灰盒期观察 🟡

# 第三部分：灰盒范围（当前裁剪）

**灰盒必做（v0.1）**：
- 移动/射击/手感（生死线，唯一 KPI）
- 一关地形 + 据点结构（窄路 + 宽据点 + 战争迷雾）
- 怪 AI：跟随/跟远加速/仇恨（视野内得分高者）
- 升级 + 子弹时间
- 基础弹幕交互词条（反射一种起步）+ 火/水两种元素
- 商店（据点内、私人货架、替队友买）
- 祭坛复活 + 鬼魂基础（拴绳/buff/搬运）
- Spike 1：Go 权威服务器 + 客户端预测（与以上并行，排期前提）

**延后（v0.2+）**：技能腐烂强化怪物（先只做"10 秒消失"，强化随数值阶段上）、狂暴（攻击分裂先顶）、第二关 + 新怪、Boss 完整设计实装、结算页、ping 系统、元素表扩展、更多武器

**远期路线图**：双轨分兵、碎片收集复活、技能槽/熔铸、橡皮筋、局外成长

# 附录：爽点对照表

高人气肉鸽的八条爽点（Balatro 700 万份、尖塔2 首日 43 万在线、Mewgenics 11.5 万在线等头部作品归纳），对照本项目承接方式：

| 爽点 | 说明 | 本项目承接 |
|---|---|---|
| ① 构筑成型（"胡了"） | 延迟满足集中兑现，1+1>2 协同高潮 | 技能≥8 取舍 + 弹幕交互词条——**"胡了"在联机里是共享事件**（队友弹幕交汇=共同见证） |
| ② 大数值爆炸 | 成型后必须看得见 | 弹幕游戏天然占优（满屏演出） |
| ③ 良随机 | 随机给玩家留干预接口 | 商店私人货架 / 位置死亡技能（用走位干预掉落） |
| ④ 短循环 | 单局 20~30 分钟即时满足 | 单局压 25 分钟，两关结构 |
| ⑤ 失败变投资 | 归因清晰 + 差一点就赢 | 据点重算翻盘窗口；鬼魂不掉线；结算页数据对比 |
| ⑥ 操作爽 | 每秒都在发生的爽点 | 弹幕走位 + 反射队友弹幕的操作上限；灰盒期唯一 KPI |
| ⑦ 风险决策 | 押注放大胜利满足 | 技能 10 秒腐烂强化怪 = 逼你做"捡不捡"的即时押注 |
| ⑧ 发现与秘密 | wiki 文化、长线留存 | 元素组合表 / 隐身流这类"规则涌现"留给玩家自己发明 |

多人专属第九条：**共同胜利的惊险瞬间**（尖塔 2 联机被记住的全是"差一点全灭"时刻）——本项目的弹幕交互、祭坛护法、挂油挂火协同全部为制造这种时刻而设。

# 一句话总结

五个痛点（死亡等待、数值乘法、分配零和、节奏绑架、联机架构）全部指向同一个前提：**服务器权威架构**。Go 后端让多数解法从"攻坚"变成"顺手能力"；而弹幕交互 + 元素组合 + 位置死亡技能，让"多人"不只是人数 ×N，而是把爽点本身变成共享事件——这是对元气骑士类竞品的结构性差异。
